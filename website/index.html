HashLink Bytecode Runtime

A faster Runner for
HashLink bytecode.

Ash runs the HashLink (.hl) bytecode your Haxe compiler already produces. Point it at a file and it runs, no changes to your project. It gets faster as it goes: the code you run most is compiled while your program is running.

Features

The ash approach to running HashLink

Run the same bytecode you already build. Ash speeds it up as it runs, ships as one binary, and can also compile your program to a native executable or to WebAssembly.

01

Faster while it runs

Your program starts immediately, and the code it runs most gets compiled in the background while it keeps going.

02

Nothing to change

Point ash at the .hl file Haxe already produces. No recompiling, no flags, no changes to your project.

03

Optimization passes

Null-check elimination, GVN/CSE, LICM, FMA fusion, DCE, tail-recursion elimination, inlining, and scalar replacement of aggregates.

04

Memory that behaves

The collector only takes the memory your program actually uses, and gives it back when it stops needing it.

05

Threads that work

sys.thread works as you expect, including in the browser. Threads waiting on a lock or a sleep never hold up the rest.

06

Runs in a browser

Build the same program to WebAssembly and ship it as a web page, threads and all.

07

Your libraries still load

The .hdll libraries you already use keep working, loaded the same way HashLink loads them.

08

One file to install

The standard library is built in. There is nothing to install beside it and no runtime to ship with your game.

Quick Setup

Install, compile, run

One script, no toolchain. Prebuilt binaries for macOS, Linux and Windows on aarch64 and x86_64.

01

Install Ash

Drops the ash binary into ~/.ash/bin and adds them to your PATH. Ash requires a 64-bit target.

$ curl -fsSL https://ash.rayzor.tech/install.sh | sh

for Windows users in PowerShell:

$ irm https://ash.rayzor.tech/install.ps1 | iex
02

Compile Haxe to bytecode

Ash runs HashLink bytecode, so build a .hl file with Haxe, or use one you already have.

$ haxe -main Main -hl main.hl
03

Run it

Give it a .hl file. Tell it what kind of program yours is and it tunes itself to match.

$ ash main.hl
$ ash --preset game main.hl # compile during load, not during play
$ ash --preset server main.hl # runs for weeks
$ ash --preset script main.hl # starts and exits
Want to build it yourself, or work on ash? The steps are in the README.
04

Build an executable

--build compiles and links in one command. It uses the C toolchain already on your machine, the same one a C program needs. Set CC if you want a different one.

$ ash --build mygame mygame.hl

Executables are built for the machine you build on. WebAssembly is the exception, and takes the same command.

$ ash --build mygame.wasm --target wasm32-wasip1 mygame.hl

There is nothing else to install: ash brings its own wasm linker. Your program behaves the same in the browser as it does natively, exceptions and all. How it works.
